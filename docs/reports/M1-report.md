# M1 report: documents core (no AI)

Brief: `BE-agent-brief.txt` v1.0, section 15 (M1) and section 16 (report format).
Verification: every claim below marked **CI** was observed in a green GitHub Actions run of `mvn verify`
(real PostgreSQL 16 through Testcontainers). Anything else is stated as not verified.

## 1. Done (mapped to the brief)
- **Section 5 / 6 data and lifecycle:** `V2` documents/versions/approvals (from the brief), `V2_1` audit + outbox,
  `V2_2` comments (these three were pulled forward, ADR-001), `V2_3` approval integrity, `V2_4` rollback flag.
- **Section 6 actions:** create document (+ draft v1), new draft (from the approved version, or `fromVersionId`
  for rollback / re-edit of a rejected version), edit draft with `If-Match`, submit, discard, reject (comment
  required), approve (full transaction: row lock, `expectedHash`, computed gates, supersede, pointer move,
  approval row, audit row, outbox event in one transaction), comments.
- **Section 12 endpoints:** `POST/GET /projects/{pid}/documents`, `GET /documents/{did}`,
  `GET/POST /documents/{did}/versions`, `GET/PATCH /document-versions/{vid}`, `POST .../submit|approve|reject|discard`,
  `GET/POST .../comments`. ETag = content hash; 428 / 412 / 409 `STALE_CONTENT` / 422 `GATE_NOT_SATISFIED`.
- **Section 13 audit:** PROJECT_CREATED/UPDATED, DOCUMENT_CREATED, VERSION_CREATED/UPDATED (hashes only)/SUBMITTED/
  APPROVED/REJECTED/DISCARDED, COMMENT_ADDED (length only), LOGIN_SUCCEEDED/FAILED, all in the same transaction as
  the change (login audit in its own transaction, see ADR-002).
- **Events:** DocumentVersionSubmitted / Approved / Rejected written to `outbox_event` (no dispatcher yet: M4).

## 2. Deviations and decisions
1. **ADR-002** changes the module dependency matrix: `project -> audit`, `document -> identity`, `identity -> audit`.
2. **Rollback flag (`V2_4`)**: brief section 6 contradicts itself (rollback parent = older version, but approve asserts
   parent == approved pointer). Resolved with an immutable `is_rollback` column; approve accepts
   `parent == approved OR is_rollback`. Owner chose this option.
3. **API_CONTRACT validation is structural, not the full OpenAPI schema.** I could not verify a swagger-parser version
   (Maven Central was unreachable from my sandbox) and avoided adding Jackson 2 to a Boot 4 / Jackson 3 app without
   being able to test it. `ContractValidator` (SnakeYAML) checks syntax, duplicate keys, `openapi` 3.0/3.1,
   `info`, paths shape, `responses` (3.0), unique `operationId`, unknown path-item fields and local `$ref`
   resolution, with line numbers. Remote `$ref`s are refused (the backend never fetches URLs). Schema objects,
   parameters, security schemes etc. are not inspected. Upgrade path: swagger-parser behind the same class.
4. **Error code `INVALID_CONTENT` (422)** for empty content on submit is mine (the brief lists only INVALID_CONTRACT).
5. **Comment permissions:** OWNER and APPROVER may comment, VIEWER may read (brief silent). Comments are allowed
   on a version in any status.
6. **Throttled logins (429) are not audited** (an attacker could fill the audit table); failed logins for unknown
   emails are audited as actor `ANONYMOUS` with the (trimmed) attempted email.
7. `If-Match: *` is deliberately not accepted for PATCH (it would defeat lost-update protection).

## 3. Tests (CI)
87 tests before 1d/1e; the figure for the final run is in the pull request. Document-related suites:
`DocumentApiTest` (read/write/list/ETag/roles), `DocumentApprovalApiTest` (flow, gates, supersede, rollback,
reject, DB hash FK, **concurrent approvals -> exactly one success**), `DocumentContractAndCommentApiTest`,
`ContractValidatorTest` (unit), `LoginAuditTest`, `ProjectAuditTest`, `DocumentSchemaTest`, `ArchitectureTest`.
Not covered: input-size limits beyond bean validation (M5), log redaction (M5), concurrency of version creation
(covered only by the row lock + the partial unique index), load behaviour.

## 4. Open questions (each with my default)
1. Should VIEWER be allowed to comment? *Default:* no.
2. Should the full OpenAPI validation (swagger-parser) replace the structural check before M5? *Default:* later,
   when a version can be verified in CI.
3. `GET /documents/{did}/versions` loads full content and drops it in the response; fine for the MVP size, revisit
   if documents grow. *Default:* keep.

## 5. Risks noticed
- Session and login throttle are in memory (single instance).
- `V2_4` replaces the `guard_document_version()` trigger function again; any future change must start from that file.
- Audit rows for unknown-email login attempts grow with attacker traffic (bounded by the 5/15min throttle per email,
  not per client).

## 6. Libraries
No new dependency in M1. SnakeYAML is used through the existing transitive dependency (springdoc/Spring Boot).
